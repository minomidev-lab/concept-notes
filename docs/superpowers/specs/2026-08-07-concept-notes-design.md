# 나만의 개념노트 — 설계 문서

- 날짜: 2026-08-07
- 상태: 사용자 승인 완료 (브레인스토밍 세션)
- 다음 단계: writing-plans 스킬로 구현 계획 작성

## 1. 목적과 성공 기준

초·중·고 과목별 개념을 체계적으로 펼쳐보고, 각 개념에 "나의 이해"를 덧붙여 쌓아가는 개인 학습 노트 사이트를 만든다.

성공 기준:

- 태블릿 브라우저에서 개념을 탐색하고, 키보드로 노트를 쓰고, 손으로 스케치를 그려 저장할 수 있다.
- 외부 누구나 URL로 접속해 노트를 열람하고 댓글을 달 수 있다.
- Claude가 파일 수정·push만으로 개념 콘텐츠를 생성·보강할 수 있다.
- 운영 비용 0원(무료 티어만 사용), 서버·DB 관리 없음.
- 콘텐츠 구조가 추후 책(PDF) 출판을 막지 않는다.

## 2. 확정된 요구사항 (브레인스토밍 결과)

| 항목 | 결정 |
|------|------|
| 콘텐츠 출처 | Claude가 교육과정 기반 초안 생성, 사용자가 다듬고 "나의 이해" 추가 |
| 과목 | 수학, 과학(물/화/생/지), 국어, 영어 — 뼈대는 4과목, 콘텐츠는 단계적 확장 |
| 손글씨 | 스케치 첨부 방식 (캔버스에 그려 이미지로 저장·삽입) |
| 공개 범위 | 전체 공개 + giscus(GitHub Discussions) 댓글 |
| 화면 구조 | 하이브리드: 사이드바 트리 탐색 + 개념 페이지 상단 초→중→고 연결 경로 |
| 아키텍처 | 정적 사이트(Astro) + GitHub 저장소를 콘텐츠 DB로 사용 |

## 3. 전체 아키텍처

**단일 진실 원천 = GitHub 저장소 하나.** 개념 마크다운, 나의 이해 노트, 스케치 이미지, 사이트 코드가 모두 한 저장소에 있다.

세 갈래의 흐름:

1. **방문자** — 배포된 정적 사이트에서 열람, giscus로 댓글.
2. **사용자(편집 모드)** — 브라우저에서 GitHub 인증 후 키보드 입력·스케치 → GitHub API로 커밋.
3. **Claude** — 로컬에서 파일 생성·수정 → push.

어느 경로든 push가 일어나면 GitHub Actions가 사이트를 재빌드해 GitHub Pages로 배포한다(1~2분).

```
[방문자]   [나: 편집 모드]   [Claude]
    ↓            ↓              ↓
        GitHub 저장소 (단일 진실 원천)
                 ↓  push 시 자동 빌드·배포
[정적 사이트]  [GitHub Discussions 댓글]  [책 파이프라인(추후)]
```

## 4. 콘텐츠 구조

개념 하나 = 폴더 하나.

```
content/
  math/                    # 과목: math / science / korean / english
    middle/                # 학교급: elementary / middle / high
      functions/           # 단원
        linear-function/   # 개념
          concept.md       # 개념 설명 (Claude 초안 + 다듬기)
          my-note.md       # 나의 이해 (사용자 전용 — Claude는 수정하지 않음)
          sketches/        # 스케치 이미지(PNG) + 원본 스트로크 데이터(JSON)
```

`concept.md` frontmatter:

- `title`: 개념 이름
- `level`: elementary | middle | high
- `prev` / `next`: 연결되는 개념의 경로 목록 (초→중→고 연결 경로 렌더링에 사용)

파일을 분리하는 이유:

1. Claude가 `concept.md`를 갱신해도 `my-note.md`는 안전하다.
2. 페이지에서 "개념 설명 vs 나의 이해"를 시각적으로 구분해 보여줄 수 있다.
3. 책 출판 시 "개념만 / 내 해설 포함" 조합 선택이 가능하다.

수식은 LaTeX 문법으로 작성하고 사이트에서 수학 조판으로 렌더링한다.

## 5. 화면 구조 (하이브리드)

- 왼쪽 사이드바: 과목 → 학교급 → 단원 → 개념 트리. 좁은 화면(태블릿 세로)에서는 햄버거 메뉴로 접힘.
- 개념 페이지 상단: `prev`/`next` 기반 연결 경로 표시 — 예: "규칙과 대응(초) ← **일차함수(중)** → 이차함수(중) · 함수의 극한(고)".
- 본문 순서: 연결 경로 → 개념 설명 → 나의 이해(색 테두리로 구분) → 댓글(giscus).
- 스케치 이미지는 나의 이해 본문 중 원하는 위치에 삽입.

## 6. 편집 흐름

**인증**: 사이트 우측 상단 "편집" 버튼 → 기기당 최초 1회 GitHub 인증. 인증 정보는 해당 기기 브라우저에만 저장. 커밋 권한은 저장소 소유자 계정에만 있으므로 다른 방문자에게는 편집 UI가 보이지 않는다.

**키보드 입력**: "나의 이해" 영역의 연필 아이콘 → 마크다운 에디터(실시간 미리보기) → 저장 시 GitHub API로 `my-note.md` 커밋. 편집자 화면에는 즉시 반영(재배포 지연을 체감하지 않음). `concept.md`도 같은 방식으로 가벼운 편집 가능.

**스케치 입력**: "스케치 추가" → 전체 화면 캔버스(펜 굵기·색·지우개) → 저장 시 PNG를 `sketches/`에 커밋하고 노트 커서 위치에 이미지 자동 삽입. 원본 스트로크 데이터(JSON)도 함께 저장해 기존 스케치를 다시 열어 이어 그릴 수 있다.

**충돌 방지**: 저장 시점에 원격에 더 새로운 버전이 있으면 "덮어쓰기 / 취소" 확인을 띄운다.

## 7. 배포·댓글·책

- **배포**: push → GitHub Actions 빌드 → GitHub Pages. 무료, 커스텀 도메인 추후 연결 가능.
- **댓글**: giscus. 댓글은 저장소 Discussions에 저장, 관리(삭제·차단)는 GitHub에서.
- **책(추후 단계)**: 마크다운 → PDF 조판 스크립트("과목 선택 → 순서 정렬 → 포함 범위 선택"). 이번 구현 범위 밖. 현 설계는 이를 막지 않는 콘텐츠 구조만 보장한다.

## 8. 에러 처리

- 편집 저장 실패(네트워크 등): 작성 내용을 브라우저 로컬에 임시 보관해 유실 방지, 재시도 버튼 제공.
- 빌드 실패: 사이트는 마지막 성공 버전 유지 — 방문자 영향 없음. 실패 원인은 GitHub Actions 로그로 확인.
- 인증 만료: 편집 시도 시 재인증 안내.

## 9. 테스트·검증

- 빌드 시 검사: 깨진 내부 링크(prev/next 경로 오류), frontmatter 필수 필드 누락.
- Playwright 스모크 테스트: 페이지 열람 → 편집 모드 진입 → 노트 작성·저장 → 스케치 저장 확인.
- 각 구현 단계마다 태블릿 뷰포트(반응형) 확인.

## 10. 단계별 로드맵

1. **1단계 — 뼈대와 열람**: 저장소 구조 + Astro 사이트(트리 탐색, 연결 경로, LaTeX 렌더링, 반응형) + 수학 1개 단원 샘플 콘텐츠 + GitHub Pages 배포.
2. **2단계 — 나의 편집**: GitHub 인증 + 마크다운 에디터 + 스케치 캔버스.
3. **3단계 — 소통**: giscus 댓글 + 4과목 콘텐츠 확장(Claude 초안 생성).
4. **4단계(추후) — 책 내보내기**: 별도 프로젝트로 진행.

각 단계는 독립적으로 배포 가능하며, 단계마다 스펙 → 계획 → 구현 → 검증 사이클을 거친다.

## 11. 범위 밖 (명시적 제외)

- 자체 회원가입/로그인 시스템 (GitHub 계정으로 충분)
- 실시간 공동 편집
- 페이지 위 자유 필기 레이어 (스케치 첨부 방식으로 대체)
- 오프라인 편집 지원
- 책 PDF 파이프라인 구현 (구조만 보장)
